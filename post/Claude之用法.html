Claude 之用法

📅 发布于：2026年11月06日 📂 技术笔记 🏷️ AI, Claude Code, 工具

它是什么

Claude Code 是一个编程代理：不只是回答问题，它还会读文件、改代码、执行命令，每个有风险的动作都先经过你的批准才会执行。它可以运行在终端（名字里的 Code 就来自命令行工具）、VS Code 扩展、桌面应用和网页版里，指令基本通用——少数只在终端可用的操作，在指令清单一节单独列出。上一篇《Claude 之思考》讲的是内部原理——ReAct 循环、三层提示词、KV 缓存；这一篇讲怎么使用：怎么输入、权限怎么设置、有哪些指令、上下文怎么管理。指令清单对照过官方文档（2026 年 11 月）；这个工具迭代很快，某条指令还在不在，以 /help 的输出为准——/vim 就是这期间刚被移除的。

三种输入

  • 自然语言。默认方式：直接描述任务，剩下的它自己决定——先读哪个文件、执行哪条命令，都是它的动作。
  • ! 前缀（仅终端）。进入 shell 模式：!git status 直接执行命令，输出进入上下文，它看到结果后接着处理。适合自己想执行一条命令、同时希望 AI 看到结果的场景——VS Code 扩展的聊天框里 ! 不生效，会被当作普通消息发送出去。
  • @ 引用。输入 @ 会弹出文件路径补全，选中后文件内容进入对话，省得再描述”就是那个改过的配置文件”。

它干活的时候你不必等着：随时可以输入并回车，消息会显示为灰色、排进队列，它做完手头的事会自动接上。

权限：先确认，再执行

它的动作分两类：只读操作（读文件、搜索）直接执行；写操作（修改文件、执行命令）先经过权限确认。确认的频率用 Shift+Tab 轮换：

模式 行为
默认 编辑和命令逐条询问
自动接受编辑 文件改动放行，命令仍询问
计划模式 只读调查，先出完整计划，批准后才动手

计划模式适合大改动：先看它打算怎么改，比改完再撤销便宜得多。还有一档完全放行（bypass permissions），一般只在沙箱或容器环境里才考虑使用。逐条的规则用 /permissions 配置——把安全命令（git status 这类）设为不再询问，把危险命令设为必须确认或直接拒绝；配置好之后，日常几乎不会被弹窗打断。/plan 可以不按 Shift+Tab、直接进入计划模式。

指令清单

输入框敲 / 会弹出补全。按用途分组：

会话与上下文

指令 作用
/clear 清空上下文、开始新会话，可以给旧会话命名存档
/compact 把历史压缩成摘要、延长会话，可以附带指示（”保留方案对比，丢弃调试输出”）
/context 列出上下文占用明细：系统提示词、工具、记忆、对话各占多少 token，还剩多少空闲
/resume 恢复历史会话
/rewind 回滚到检查点，对话和文件一起恢复（按两次 Esc 呼出菜单）
/export 导出对话为文本

模型与设置

指令 作用
/model 切换模型，方向键同时调整思考力度
/effort 单独调整思考力度，low 到 max 五档
/fast 快速模式：加快输出速度，不换成小模型
/config 设置面板，也可以直接设置一项（如 /config theme=dark）
/output-style 切换输出风格：/output-style 风格名（concise、proactive 等；不带参数只列出可选风格，恢复默认用 default）
/terminal-setup 给终端设置 Shift+Enter 换行快捷键

项目与集成

指令 作用
/init 通读项目，生成 CLAUDE.md 初稿
/memory 编辑各层级的记忆文件
/add-dir 给会话添加一个工作目录
/mcp 管理 MCP 服务器（接入外部工具）
/hooks 配置钩子：在指定事件发生时自动执行脚本
/ide 连接 IDE，共享选中内容和诊断信息

信息与审查

指令 作用
/status 版本、账号、连接状态
/usage 用量与花费（/cost 是它的旧别名）
/doctor 检查安装是否有问题
/release-notes 查看更新日志
/code-review 审查当前改动、找 bug（别名 /review）
/security-review 检查当前分支相对默认分支的改动有没有安全漏洞

终端和插件（VS Code 扩展）的差异

绝大多数斜杠指令两边通用，例外是这些：

指令 / 操作 终端 VS Code 插件
上表其余指令 可用 可用
! shell 模式 可用 不可用，会作为普通消息发出
? 帮助面板、Ctrl+O/R/T/B 快捷键 可用 不可用
/terminal-setup 可用，设置 Shift+Enter 绑定 不适用
/ide 可用，连接 VS Code（共享选中、诊断、diff） 不可用——扩展里连接已经内置，不需要再连
/bug 文本报告 打开扩展自己的反馈对话框

各版本之间指令变动不小，完整清单在官方文档（code.claude.com/docs）。

上下文怎么管理

上下文窗口是稀缺资源，而且不是全部留给对话——系统提示词、工具定义、记忆文件会先占掉一部分。/context 列出这份明细（下面是一次实际输出，做了合并和删减）：

类别 token 占比
系统提示词 + 工具定义 14.1k 1.4%
记忆与技能 3.3k 0.3%
对话消息 25.3k 2.5%
自动压缩缓冲 33k 3.3%
空闲 929.2k 92.9%

这张表正好对应上一篇的三层提示词：第一行是第一层的固定内核，第二行是第二层的注入前缀，第三行是第三层的交互记录——也就是 ReAct 循环本体，是唯一随会话变长的一行；前两行是每次开场的固定开销（本例约 17k）。空闲空间和压缩缓冲不属于任何一层。这个分层同时也是缓存分层：第一、二层是稳定的前缀，KV 缓存最容易命中；第三层只在末尾追加——「稳定的放前，易变的放后」，说的就是这张表的排法。

表末尾那项”自动压缩缓冲”是预留的余量：历史接近上限时，框架会自动把旧对话压缩成摘要，会话不会因为窗口用满而突然中断。

什么时候用哪个：换任务就用 /clear——旧的历史会残留下来，把新任务的方向带偏，还白白消耗 token；同一个长任务、窗口快满了才用 /compact。压缩的代价是前缀被重写、KV 缓存全部失效，下一个请求要按全价重新计算，原理见上一篇的缓存一节。/rewind 解决另一类问题：回滚到之前的检查点，对话和文件一起恢复——配合计划模式使用，批准计划之前和之后的状态都留着，随时可以回去。

收尾

清单看着杂，设计逻辑只有两条：让模型自主行动（agent 循环），同时用框架的硬约束兜底（权限确认、检查点、沙箱、压缩缓冲）。用得熟练的标志不是背下全部指令，而是知道每项约束该放到多松或多紧——权限放开多少、上下文什么时候压缩、哪些命令放进沙箱执行。
